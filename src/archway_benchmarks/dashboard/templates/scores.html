Headline column is Regenerated · lenient: TypeEvalPy's paper-era predicate (file + line + name) applied to each tool's output against the current GT. That's the fair head-to-head: a small Δ vs Historical reflects GT drift since publication. Archway is the bold row.

Why two scorers?
In Oct 2025 (commit 2f7c6056) TypeEvalPy added a stricter is_same_element that requires col_offset to match. None of the existing tool runners (Jedi, Scalpel, HeaderGen) emit a column, so they all score 0 under that scorer — a runner-format artifact, not an inference result. The lenient scorer is what generated the published board; the strict column is shown only as a transparency note and is shaded grey.
